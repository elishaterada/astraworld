# Stable local development URLs — 2026-09-07

User requested the installed Vercel Portless CLI in place of manually selected frontend ports. This is local tooling only; M2 mechanics and production deployment are unchanged.

`npm run dev` runs `scripts/dev-local.mjs`: ensure the shared Portless proxy, obtain named service URLs, reuse existing local Redis or start temporary Redis, then run two gateways and Next.js under Portless. The gateway launcher accepts Portless's PORT when GAME_PORT is unset. The frontend receives the public gateway URLs; gateways allow the actual frontend origin. Next allows the specific astraworld.localhost development origin. `npm run dev:next` retains direct Next startup for fixed-port test fixtures.

Installed Portless 0.15.6 / Node 24.13.0 initialized HTTPS and trusted its local CA. Port 443 required an unavailable interactive administrator password, so Portless selected its fixed fallback proxy port 1355. Active public URLs are https://astraworld.localhost:1355, https://astraworld-game-a.localhost:1355 and https://astraworld-game-b.localhost:1355. The internal ports selected for this run were 4862, 4638 and 4697 respectively; these are not application configuration. The launcher derives origins and endpoint URLs from `portless get`, so it also supports a proxy configured for 443.

Verification: typecheck passed. Agent-browser loaded the trusted HTTPS page without certificate bypass and reported no errors. `BASE_URL=https://astraworld.localhost:1355 GATHER_EVIDENCE_PREFIX=docs/milestones/evidence/m2-portless npx playwright test tests/e2e/gathering.spec.ts` passed in 6.8 seconds. Two independent authenticated browser contexts joined, raced on a bush, observed tree harvesting and reloaded inventory through the HTTPS/WebSocket proxy. See [results](evidence/m2-portless-browser.json).

The launcher only stops child processes it started; it does not stop the shared proxy or a pre-existing Redis process. Its newly started Redis has no disk persistence, consistent with the prior local workflow. The production build/full simulation suite were not rerun for this local launcher change. `next-env.d.ts` is regenerated by Next dev to point to dev route types. No new service was provisioned or deployed. M3 remains unstarted.
